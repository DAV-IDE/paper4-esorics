# Synthetic Factorial — Provenance and Reproducibility Note

This document explains how the 45-run entropy factorial that backs
Paper 4 Table 6 (§5.1 sensitivity analysis) is handled inside
`paper4-esorics`.

## Summary

The 45-run factorial (3 scenarios × 5 configurations × 3 entropy
metrics) is **not** generated by any script in `paper4-esorics`.
It is generated by an upstream companion pipeline. Two curated
output files are imported here as a **verified static snapshot**,
pinned by SHA-256.

## What is in this repo (paper4-esorics)

Under `results/synthetic/`:

| File | Role |
| --- | --- |
| `results_ready_summary.csv` | 45-row data table (scenario, config, W, stride, metric, t\_detect, delay, pre-event FPs, peak \|ΔH\|). Backs Table 6. |
| `results_ready_summary.tex` | Publication-ready LaTeX `longtable`. Rendered as Table 6 in `paper/main_v4.tex`. |
| `provenance.json` | Machine-readable manifest: source repo, commit SHA, raw URLs, SHA-256 of each file, paper cross-references, license status. |

Verification script: `scripts/verify_synthetic_provenance.py`. It
recomputes SHA-256 locally and compares against `provenance.json`.
Exit code 0 means all imported files are unchanged; exit code 1
means at least one file is missing or altered.

## What is NOT in this repo

The upstream generative pipeline is intentionally **not** reproduced
in `paper4-esorics`. In particular, `paper4-esorics` does not contain:

- The synthetic scenario generator (stable / drift / shock).
- The RDF triplification / Fuseki-based ingest of the synthetic runs.
- The sliding-window entropy computation over `C1..C5`.
- The plot-generation scripts for the entropy curves.
- The Docker / Docker Compose stack used to run the above.

All of these live in the companion repository:

> https://github.com/LoreBerto03/psi-risk-dt-pipeline
> Commit pinned: `edac16e9f0edd99a949e2aa7e1e92ae505e2027e`
> (2026-06-11, branch `master`)

That repository is also cited as reference **[3]** in
`paper/main_v4.tex` and is the sole source of truth for the
generative pipeline.

## Why a static snapshot and not a submodule / re-implementation

Three factors drove this choice:

1. **Reviewer experience.** ESORICS reviewers checking the artefact
   should be able to `git clone` `paper4-esorics` and reproduce the
   claims in §5.2–§5.4 (real CIC-IDS2017 rerun, τ sweep, SPARQL
   scaling) without also cloning, building, and running a Fuseki /
   Docker stack that has nothing to do with the ESORICS contribution.
   Table 6 is background evidence for §5.1 and does not need
   regeneration during review.
2. **Avoiding implementation drift.** Re-implementing the upstream
   pipeline inside `paper4-esorics` would create two divergent code
   paths generating a number series (Table 6) whose values are
   already cited in the paper. A static snapshot with SHA-256
   provenance is the honest way to say *these are the exact bytes
   Table 6 was rendered from*.
3. **No submodule.** A `git submodule` for a repo that has no
   explicit license would just push the license question one level
   deeper without solving it, and would complicate every `git clone`
   for reviewers.

## How to regenerate the 45-run factorial from scratch

If you want to *re-derive* `results_ready_summary.csv` and
`.tex` rather than trust the pinned snapshot:

1. Clone the upstream companion repository:

    ```bash
    git clone https://github.com/LoreBerto03/psi-risk-dt-pipeline.git
    cd psi-risk-dt-pipeline
    git checkout edac16e9f0edd99a949e2aa7e1e92ae505e2027e
    ```

2. Follow its `README.md`: `bash run_all.sh` runs the full pipeline
   (Docker + Fuseki + entropy computation + table export) with a
   fixed seed (`SYNTHETIC_SEED = 42`) and produces
   `results/tables/final/results_ready_summary.{csv,tex}`.

3. Compare against the files under `results/synthetic/` in this
   repository. They should be byte-identical to the pinned commit.

## How to update the snapshot to a newer companion commit

1. Choose a new upstream commit SHA and download the two files:

    ```bash
    SHA=<new_commit_sha>
    curl -sSL "https://raw.githubusercontent.com/LoreBerto03/psi-risk-dt-pipeline/${SHA}/results/tables/final/results_ready_summary.csv" \
      -o results/synthetic/results_ready_summary.csv
    curl -sSL "https://raw.githubusercontent.com/LoreBerto03/psi-risk-dt-pipeline/${SHA}/results/tables/final/results_ready_summary.tex" \
      -o results/synthetic/results_ready_summary.tex
    ```

2. Recompute SHA-256:

    ```bash
    sha256sum results/synthetic/results_ready_summary.csv results/synthetic/results_ready_summary.tex
    ```

3. Update `results/synthetic/provenance.json`:
   - `source.commit_sha`
   - `source.commit_date`
   - `imported_files[*].sha256`
   - `imported_files[*].source_url` (the SHA fragment)
   - `import.date`

4. Verify: `python scripts/verify_synthetic_provenance.py` should
   return exit code 0.

5. Also update Table 6 in `paper/main_v4.tex` if any numeric value
   changed, and record the diff in `CHANGELOG.md`. The empirical
   honesty rule for this repo requires that any change in ordering
   or magnitude be reported as an empirical finding, not silently
   overwritten.
